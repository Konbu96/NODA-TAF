# Step 1 設計：毎日開くアプリにする

> 企画書（[00_project-overview.md](00_project-overview.md)）の Step 1 の設計資料です。
> 技術構成は [01_tech-stack.md](01_tech-stack.md) を参照。

---

## 1. Step 1 の範囲

| 機能 | 内容 |
| --- | --- |
| ログイン | Google アカウントでログイン。部員名簿にない人は使えない |
| 入部申請・承認 | 初めてログインした人が名前・学年を入力して申請し、顧問・キャプテンが承認する |
| 部員名簿・権限 | 顧問が役職の設定をする |
| 練習メニュー（A） | 日ごとのメニューを登録・確認する。アプリを開いて最初に表示される画面 |
| マイページ（B） | ゼッケン番号・専門種目・PB などを表示・編集する |
| 競技場代の計算（E） | 競技場の日に、部員が自分で「行く／行かない」を押し、人数と代金を自動計算する |

Step 1 に **入れないもの**

- 今月の目標の表示：振り返り（Step 4）と一緒に作る。Step 1 では表示する場所だけ用意しておく
- PB の自動更新：大会記録（Step 2）と一緒に作る。Step 1 では手入力
- 他の部員の記録を見る：Step 2 で作る

### 承認待ちの知らせ方

- 顧問・キャプテンがアプリを開くと、管理タブに「承認待ち 3 件」のようなバッジを表示する
- スマホへの通知（プッシュ通知）も送りたい。ただし作るのに手間がかかり、iPhone はホーム画面にアプリを追加した人しか受け取れないため、Step 1 ではバッジのみとし、通知はあとの Step で作る

### 画面の流れ

```
アプリを開く
  ├─ ログインしていない → 1. ログイン
  └─ ログインしている
       ├─ 名簿にない → 2. 入部申請 → 2-2. 承認待ち
       ├─ 申請中 → 2-2. 承認待ち
       └─ 承認済み → 3. 練習メニュー（ホーム）
                          ├─ 編集ボタン（権限がある人のみ）→ 4. 練習メニュー編集
                          ├─ マイページタブ → 5. マイページ → 6. プロフィール編集
                          └─ 管理タブ（顧問・キャプテン）→ 7. 部員名簿 → 8. 部員の承認・編集
```

### 競技場の日の流れ

1. メニューを登録する人が「競技場の日」にチェックを入れる
2. 部員はメニュー画面で「行く／行かない」を押す（押していない人は「未回答」）
3. 冬季料金が必要な日は、誰かが「冬季料金」をオンにする（全員が切り替えられる）
4. 画面に参加人数・合計金額・自分の金額が自動で表示される
5. 「参加者を見る」を押すと、参加者・不参加・未回答の名前と金額の一覧が見られる（集金のときに使う）

- マネージャー・顧問には「行く／行かない」ボタンを出さない（料金がかからないため）
- 押し間違いなどは、顧問・キャプテン・副キャプテン・マネージャーがあとから直せる

### メニューを見られる期間

- **前日・今日・1 週間後まで** を表示する（それより前のメニューは表示しない）
- 登録も 1 週間後まで。基本は当日に入力する

## 3. データの形（Firestore）

### members（部員名簿）

ドキュメント ID は **メールアドレス（小文字）**。ログインした人のメールアドレスで名簿を探し、登録されているか・役職は何かを判定します。

| 項目 | 型 | 例 | 説明 | 編集できる人 |
| --- | --- | --- | --- | --- |
| name | 文字列 | 野田 太郎 | 名前 | 顧問 |
| email | 文字列 | taro@gmail.com | ログインに使う Google アカウント | 顧問 |
| status | 文字列 | approved | `pending`（承認待ち）／`approved`（承認済み）。申請時は pending で作られる | 顧問・キャプテン |
| role | 文字列 | member | `adviser`（顧問）／`captain`／`viceCaptain`／`manager`／`member`。申請時は member | 顧問 |
| isAdmin | 真偽値 | false | 開発者。顧問と同じ権限を持つ | 顧問 |
| graduationYear | 数値 | 2029 | 高校卒業予定の年度。学年はここから自動で計算する（顧問は空欄） | 顧問 |
| bibNumber | 文字列 | 123 | ゼッケン番号 | 本人・顧問・キャプテン・マネージャー |
| events | 文字列の配列 | ["100m", "200m"] | 専門種目。中学・高校の公式種目の一覧から選ぶ | 本人・顧問・キャプテン・マネージャー |
| personalBests | 一覧 | 下の表を参照 | PB（Step 1 では手入力） | 本人・顧問・キャプテン・マネージャー |
| updatedAt | 日時 | | 最終更新日時 | 自動 |

personalBests の中身（種目ごと）

| 項目 | 型 | 例 |
| --- | --- | --- |
| event | 文字列 | 100m |
| mark | 文字列 | 00:12.34（走る種目）／06.12m（距離を測る種目） |
| date | 日付 | 2026-09-15 |
| meetName | 文字列 | 〇〇記録会 |

PB の書き方（入力欄の形を固定する）

| 種目の種類 | 書き方 | 例 |
| --- | --- | --- |
| 走る種目（短距離・中長距離・ハードル・リレー・競歩） | `分:秒.1/100秒`（00:00.00） | 100m → 00:12.34、1500m → 04:35.20 |
| 距離を測る種目（跳躍・投てき） | `00.00m` | 走幅跳 → 06.12m、砲丸投 → 11.50m |

> グラフや並べ替えのために、保存するときは「秒」や「m」の数値にも変換しておきます（例：04:35.20 → 275.20 秒）。
| 混成競技（四種競技・八種競技など） | `0000点` | 四種競技 → 2500点 |

### 学年の自動計算とは

学年（中 1〜高 3）をそのまま保存すると、毎年 4 月に全員の学年を 1 つずつ書き換える必要があります。卒業後に誰かが忘れると、学年がずれたままになります。

そこで、学年の代わりに **「高校を卒業する年度」** を保存し、アプリが今日の日付から学年を計算して表示します。

| 高校を卒業する年度 | 2026 年度の学年 | 2027 年 4 月以降 |
| --- | --- | --- |
| 2026（2027 年 3 月卒業） | 高 3 | 卒業 |
| 2028 | 高 1 | 高 2 |
| 2031 | 中 1 | 中 2 |

- 部員を登録するときに一度入力するだけで、あとは 4 月に自動で学年が上がる
- 競技場代の計算（中学生 60 円・高校生 120 円）も、この学年をもとに自動で判定できる

### practiceMenus（練習メニュー）

ドキュメント ID は **日付（YYYY-MM-DD）**。1 日 1 件。

| 項目 | 型 | 例 | 説明 |
| --- | --- | --- | --- |
| date | 文字列 | 2026-10-24 | 日付 |
| place | 文字列 | 競技場 | 練習の場所（選択肢から選ぶ） |
| warmUp | 文字列の配列 | ["10種", "動き作り", "マークドリル"] | アップの内容（選択肢から選ぶ） |
| general | 一覧 | 下の「練習の項目」を参照 | 全体のメニュー |
| special | 一覧 | 下の「練習の項目」を参照 | 専門練習のメニュー（ない日は空） |
| note | 文字列 | スパイク持参 | 連絡事項（自由に書ける） |
| isStadium | 真偽値 | true | 競技場の日か。場所で「競技場」を選ぶと自動で true になる |
| isWinterRate | 真偽値 | false | 冬季料金（+50 円）を適用するか。全員が切り替えられる |
| updatedBy | 文字列 | captain@gmail.com | 最後に編集した人 |
| updatedAt | 日時 | | 最終更新日時 |

練習の項目（general・special の中身。1 つの練習につき 1 件）

| 項目 | 型 | 例 | 説明 |
| --- | --- | --- | --- |
| type | 文字列 | テンポ走 | 練習の種類（選択肢から選ぶ） |
| distance | 文字列 | 150m | 距離（選択肢から選ぶ。補強など距離がない練習は空欄） |
| reps | 数値 | 5 | 本数（空欄でもよい） |
| sets | 数値 | 2 | セット数（空欄でもよい） |
| memo | 文字列 | レスト 3 分 | 補足（自由に書ける） |

表示の例：`テンポ走 150m × 5 本 × 2 セット（レスト 3 分）`、`補強 5分間腹筋`

### practiceOptions（メニューの選択肢）

練習の場所・アップの内容・練習の種類・距離の選択肢をまとめて保存します。担当者（顧問・キャプテン・副キャプテン・マネージャー）が画面から追加・削除できます。

| 項目 | 型 | 最初の一覧 |
| --- | --- | --- |
| places | 文字列の配列 | 学校、競技場 |
| warmUps | 文字列の配列 | 倒立・体幹、10種、動き作り、アクティベーションドリル、ハードルドリル、マークドリル |
| types | 文字列の配列 | テンポ走、スタブロ、並走バトン、台ドロップ、補強 5分間腹筋、補強 腿上げ＋補強 10分間、補強 2分間腹筋 |
| distances | 文字列の配列 | 100m、120m、150m、200m、250m、300m |

> ダウンは決まった内容がないため、選択肢を作らない。必要な日は連絡事項（note）に書く。

### practiceMenus/{日付}/attendance（競技場の日の参加）

練習メニューの下に、部員 1 人につき 1 件保存します。ドキュメント ID は **メールアドレス**。

| 項目 | 型 | 例 | 説明 |
| --- | --- | --- | --- |
| going | 真偽値 | true | 行く（true）／行かない（false）。記録がない人は「未回答」 |
| updatedBy | 文字列 | taro@gmail.com | 最後に押した人（本人 or 担当者） |
| updatedAt | 日時 | | 最終更新日時 |

> 金額は保存せず、表示するたびに「学年」「その日の冬季料金のオン／オフ」「下の settings の料金」から計算します。料金を変えると過去の日も新しい料金で表示されますが、メニューは前日分までしか見られないため問題ありません。

### settings/fees（料金の設定）

1 件だけのデータです。料金が変わったら、顧問がここを書き換えます。

| 項目 | 型 | 例 | 説明 |
| --- | --- | --- | --- |
| juniorHigh | 数値 | 60 | 中学生の通常料金 |
| highSchool | 数値 | 120 | 高校生の通常料金 |
| winterExtra | 数値 | 50 | 冬季料金の上乗せ分 |

## 4. 権限（Firestore セキュリティルール）

画面でボタンを隠すだけでなく、データベース側でも読み書きを制限します。

| データ | 読む | 作る・編集・削除 |
| --- | --- | --- |
| members（名前・役職・学年など） | 名簿に登録された人 | 顧問・開発者 |
| members（bibNumber・events・personalBests） | 名簿に登録された人 | 本人・顧問・キャプテン・マネージャー・開発者 |
| practiceMenus | 名簿に登録された人 | 顧問・キャプテン・副キャプテン・マネージャー・開発者 |
| practiceMenus の isWinterRate だけ | 名簿に登録された人 | 名簿に登録された人（全員） |
| attendance（自分の分） | 名簿に登録された人 | 本人 |
| attendance（他の人の分） | 名簿に登録された人 | 顧問・キャプテン・副キャプテン・マネージャー・開発者 |
| settings/fees | 名簿に登録された人 | 顧問・開発者 |
| members の承認（status の変更） | ― | 顧問・キャプテン・開発者 |
| members の削除（卒業・退部） | ― | 顧問・キャプテン・開発者 |
| practiceOptions | 名簿に登録された人 | 顧問・キャプテン・副キャプテン・マネージャー・開発者 |

ルールの考え方（イメージ）

```
// ログインしている人のメールアドレスで名簿を探す
function me() {
  return get(/databases/$(database)/documents/members/$(request.auth.token.email.lower())).data;
}
function isMember()  { return request.auth != null && me().active == true; }
function isAdviser() { return isMember() && (me().role == "adviser" || me().isAdmin == true); }
function canEditMenu() {
  return isMember() && (isAdviser() || me().role in ["captain", "viceCaptain", "manager"]);
}
function canEditProfile(email) {
  return isMember() && (request.auth.token.email.lower() == email
    || isAdviser() || me().role in ["captain", "manager"]);
}
```
