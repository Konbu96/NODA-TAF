## 1. 背景

- 中高の陸上競技部で使う Web アプリを作りたい
- 作る人は部員（開発者）。開発のため、アプリ内では顧問と同じ権限を持つ
- きっかけ
  - 部活内の面倒な仕事をアプリで効率化したい
  - バラバラになっている情報をアプリ 1 つにまとめたい
  - 部員それぞれが自分の記録を残し、タイムの伸びや調子の悪い時期をあとから見返せるようにしたい

## 2. 目的

1. **情報を 1 か所にまとめる**：練習メニュー・大会情報・記録・目標を、LINE・紙・口頭・ノート・スプレッドシートから 1 つのアプリに集める
2. **面倒な作業を減らす**：競技場代の計算や月末の振り返りなど、毎回手作業でやっていることを自動化・簡単にする
3. **成長を見える化する**：個人の記録をグラフで見られるようにし、伸びや不調に気づけるようにする

## 3. 現状

| 項目 | いまのやり方 | 困っていること |
| --- | --- | --- |
| 連絡・お知らせ | LINE | 他の情報に埋もれる（要確認） |
| 練習メニュー | 口頭／紙／LINE と日によってバラバラ | **把握しづらい（一番の困りごと）** |
| 大会の記録 | 基本的にとっていない | 自分の伸びがわからない |
| 練習の記録 | 特定の練習だけノートに記録 | 見返しにくい・グラフにできない |

| 前期の目標 | スプレッドシートにまとめている | 振り返りのときに別の場所を見に行く必要がある |

## 5. 機能ごとの仕様メモ

### E. 競技場代の計算

1 人あたりの料金（1 回分）

| 区分 | 通常 | 冬季料金（電気代 +50 円） |
| --- | --- | --- |
| 中学生 | 60 円 | 110 円 |
| 高校生 | 120 円 | 170 円 |

- 参加者を選ぶと、1 人ずつの金額と合計を表示する
- **料金がかかるのは走った人だけ**。マネージャーと顧問は払わないので、参加者の候補に出さない
- **冬季料金は期間で決めず、その日ごとにオン／オフを切り替える**（電気代がかかるかは日によって違うため）。切り替えは全員ができる
- 料金は年度によって変わる可能性があるので、アプリ内の設定で変えられるようにする
- 集金の記録（払った・払っていない）は不要

### F. 月末の振り返り

| # | 質問 | 回答の形式 |
| --- | --- | --- |
| 1 | あなたの先月の個人目標は何でしたか？ | 自由記述（先月の質問 4 を自動で入れておく） |
| 2 | 目標をどのくらい達成できたか、自分が思うものを選んでください | 5 段階（1 = 達成できなかった 〜 5 = 完璧に達成できた） |
| 3 | この 1 か月で、目標のどの部分が達成できたか・できなかったか、新たに生まれた課題について具体的に書いてください | 自由記述 |
| 4 | 上記の内容や前期の目標を参考に、来月の個人目標を入力してください | 自由記述 |

- **毎月 25 日に、その月の振り返りフォームが自動で出る**。締め切りは設けない（次の 25 日に次のフォームが出るまで提出できる）
- **自分の今月の目標は、次の目標を設定するまで練習メニュー画面（最初に開く画面）に表示する**
- 前期の目標（いまスプレッドシートにまとめているもの）もアプリ内で見られるようにする
- 公開範囲
  - 来月の目標（質問 4）：全員が見られる。ただし常に表示はせず、見たい人が開いたときだけ表示する
  - 質問 1〜3：本人・顧問・キャプテンだけ
- 提出状況
  - 「28 人中 20 人提出済み」のような人数と、**未提出の人の名前**を全員が見られる
  - 未提出者の名前は、フォームが出た 25 日から表示する
  - 「未提出：〇〇さん」のように事実だけを書き、責めるような言い方にしない
  - 未提出の本人の画面には「振り返りが未提出です」とお知らせを出す
- 達成度のグラフは作らない

### 他の部員の記録を見る（見づらくならない工夫）

28 人分が一度に並ぶと見づらいので、最初は必要なものだけを表示します。

- **最初は自分のページを表示**：他の人の情報は、見に行ったときだけ表示する
- **種目でしぼる**：「100m」を選ぶと、100m に出ている人だけを表示する
- **学年・ブロックでしぼる**：中学・高校、短距離・長距離などで切り替える
- **ランキング形式**：種目ごとに PB の良い順に並べ、上位だけを表示する
- **お気に入り**：同じ種目のライバルや仲間を登録して、すぐ見られるようにする

## 6. 段階的な開発計画（案）

まず小さく作って部内で使ってもらい、反応を見ながら機能を足していきます。

| 段階 | ゴール | 入れる機能 |
| --- | --- | --- |
| Step 1 | 毎日開くアプリにする | ログイン、部員名簿、権限、マイページ（B）、練習メニュー（A） |
| Step 2 | 記録を残せるようにする | 大会記録の入力＋グラフ、PB 自動更新（C）、他の部員の記録を見る |
| Step 3 | 大会まわりをまとめる | 大会情報（D）、大会記録とのひもづけ |
| Step 4 | 面倒な作業をなくす | 競技場代の計算（E）、月末の振り返り（F） |
| Step 5 | もっと便利にする | 練習記録・調子メモ（G）、お知らせなど |

## 7. 技術・運用の前提

| 項目 | 内容 |
| --- | --- |
| 使う端末 | スマホのみ（スマホ画面を前提にデザインする） |
| 公開範囲 | 部内のみ（ログインが必要） |
| 予算 | **完全無料**（無料枠の範囲で運用する） |
| 引き継ぎ | 卒業後も使い続けられるようにする（詳細はあとで検討） |
| 技術構成 | Next.js ＋ Firebase、公開は Vercel（詳細は [01_tech-stack.md](01_tech-stack.md)） |
| ログイン | Google アカウント（部員名簿に登録された人だけが使える） |

### 技術選びの観点

- **無料で使い続けられるか**：無料枠の上限や、使わない期間があると停止されないか
- **卒業後も動くか**：アカウントを個人ではなく部の名義にできるか
- **後輩が直せるか**：作った人がいなくなっても、設定の変更や年度更新ができるか
- **個人情報を守れるか**：部員の名前や記録を扱うため、部外の人に見られない仕組みにする

### 引き継ぎの方針

部専用のアカウントを新しく作り、アプリのサーバーやデータはそこで管理する方向で進める。具体的な手順は開発が進んでから決める。
