# Step 3 設計：大会まわりをまとめる

> 企画書（[00_project-overview.md](00_project-overview.md)）の Step 3 の設計資料です。
> Step 2 の設計は [03_step2-design.md](03_step2-design.md) を参照。

---

## 1. Step 3 の範囲

| 機能 | 内容 |
| --- | --- |
| 大会情報（D） | 大会ごとの日程・会場・出場要項のリンクを登録し、部員が確認できる |
| エントリー | 部員が自分で、どの種目に出るかを入力する |
| 大会記録とのひもづけ | Step 2 の記録入力で、登録済みの大会を選べるようにする |

## 2. 画面

右下の丸ボタンの行き先に「大会」を追加し、4 つにします（丸ボタン・ヘッダー・☰ の決まりは [02_step1-design.md](02_step1-design.md) 参照）。

| 行き先 | 表示する人 |
| --- | --- |
| メニュー | 全員 |
| 大会 | 全員 |
| 部員 | 全員 |
| マイページ | 全員 |

| # | 画面 | URL | 内容 | 見られる人 |
| --- | --- | --- | --- | --- |
| 13 | 大会一覧 | `/meets` | これからの大会と過去の大会の一覧 | 全員 |
| 14 | 大会の詳細 | `/meets/detail?id=xxx` | 日程・会場・出場要項のリンク・誰がどの種目に出るか | 全員 |
| 15 | 大会の登録・編集 | `/meets/edit?id=xxx` | 大会情報の登録・編集・削除 | 顧問・キャプテン・副キャプテン・マネージャー |
| 16 | エントリーの入力 | `/meets/entry?id=xxx` | 自分が出る種目を選ぶ | 全員（自分の分） |

## 3. 大会情報として残すもの

| 項目 | 例 | 説明 |
| --- | --- | --- |
| 大会名 | 〇〇記録会 | |
| 日程 | 2026-11-08〜2026-11-09 | 1 日だけの大会もある |
| 会場 | 〇〇陸上競技場 | |
| 出場要項 | https://... | 公式の要項ページや PDF のリンク |
| エントリー | 山田 太郎：100m、200m | 部員が自分で入力する |

### エントリー

- 部員が自分で出る種目を選ぶ。顧問の確認はなく、入力したらそのまま表示される
- 締め切りはなく、大会当日まで変えられる。間違いは担当者（顧問・キャプテン・副キャプテン・マネージャー）が直せる

### 大会が終わったあと

- メニュー画面にお知らせの欄は出さない。代わりに、丸ボタンの行き先「大会」の角に、記録の入力待ちの件数（例：「1」）を表示する。丸ボタンが閉じているときは、丸ボタンの角に点をつける
- 大会一覧では、記録の入力待ちの大会に印をつける。押すと記録の入力画面が開き、大会名・日付・種目は最初から入っている。記録と風速だけ入れればよい
- 全種目の記録を入れたら、印は消える

### 大会の詳細ページ

```
┌──────────────────────────┐
│ ◀ 〇〇記録会                │
├──────────────────────────┤
│ 11月8日（日）〜9日（月）     │
│ 〇〇陸上競技場              │
│ 出場要項を見る ↗            │
├──────────────────────────┤
│ エントリー（12人）           │
│  100m  山田、佐藤、鈴木…    │
│  200m  山田、田中           │
│  走幅跳 高橋               │
│    [ 自分のエントリーを入力 ]│
├──────────────────────────┤
│ 結果（大会が終わったら表示）  │
│  100m 山田 00:11.52 🎉PB    │
│  100m 佐藤 00:11.90         │
└──────────────────────────┘
```

- エントリーは種目ごとにまとめて表示する
- 大会が終わったら、部員が入力した記録を種目ごとに表示する。PB には印をつける

## 4. データの形（Firestore）

### meets（大会情報）

| 項目 | 型 | 例 | 説明 |
| --- | --- | --- | --- |
| name | 文字列 | 〇〇記録会 | 大会名 |
| startDate | 文字列 | 2026-11-08 | 開始日 |
| endDate | 文字列 | 2026-11-09 | 終了日（1 日だけなら開始日と同じ） |
| venue | 文字列 | 〇〇陸上競技場 | 会場 |
| guidelineUrl | 文字列 | https://... | 出場要項のリンク |
| updatedBy | 文字列 | | 最後に編集した人 |
| updatedAt | 日時 | | 最終更新日時 |

### meets/{大会ID}/entries（エントリー）

部員 1 人につき 1 件。ドキュメント ID はメールアドレス。

| 項目 | 型 | 例 |
| --- | --- | --- |
| events | 文字列の配列 | ["100m", "200m"] |
| updatedAt | 日時 | |

### records に足すもの

| 項目 | 型 | 説明 |
| --- | --- | --- |
| meetId | 文字列 | 登録済みの大会から選んだときの大会 ID（自由入力のときは空） |

### 権限

| データ | 読む | 作る・編集・削除 |
| --- | --- | --- |
| meets | 名簿に登録された人 | 顧問・キャプテン・副キャプテン・マネージャー・開発者 |
| entries（自分の分） | 名簿に登録された人 | 本人 |
| entries（他の人の分） | 名簿に登録された人 | 顧問・キャプテン・副キャプテン・マネージャー・開発者 |

## 5. 決定ログ

| 日付 | 決めたこと | 理由 |
| --- | --- | --- |
| 2026-10-23 | 大会情報は日程・会場・出場要項のリンク・エントリーを確認できるようにする | 大会の情報を 1 か所にまとめるため |
| 2026-10-23 | 大会情報は顧問・キャプテン・副キャプテン・マネージャーが登録する | 企画書の権限に合わせるため |
| 2026-10-23 | 丸ボタンの行き先に「大会」を追加する | 大会の情報をすぐ見られるようにするため |
| 2026-10-23 | 記録入力のお知らせはメニュー画面に出さず、「大会」の角に件数を表示する | いらない要素を減らすため |
| 2026-10-23 | エントリーは部員が自分で入力する | 担当者の負担を減らすため |
| 2026-10-23 | エントリーに顧問の確認と締め切りは設けない | まずはシンプルにする。間違いは担当者が直せる |
| 2026-10-23 | 大会後、エントリーした人に記録の入力を促す | 記録の入れ忘れを防ぐため |
| 2026-10-23 | 大会の詳細ページに、部員の結果を種目ごとにまとめて表示する | 特定の大会での記録を確認できるようにするため |
