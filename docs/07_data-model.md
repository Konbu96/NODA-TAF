# データの形（データモデル）

> Step 1〜5 の資料に分かれて書いていたデータの形を、1 つにまとめた資料です。
> **データの形はこの資料を正とします。** Step ごとの資料と食い違うときは、こちらに合わせます。

---

## 1. 言葉の整理

Firestore は、データを次の 3 段で保存します。

| 言葉 | 意味 | 例 |
| --- | --- | --- |
| コレクション | 同じ種類のデータを入れる箱 | `members`（部員の箱） |
| ドキュメント | 箱の中の 1 件 | 部員 1 人分 |
| フィールド | 1 件の中の項目 | 名前、学年 |

ドキュメントの下に、さらにコレクションを置くこともできます（サブコレクション）。例：`practiceMenus/2026-10-27/attendance`（10 月 27 日の練習メニューの下にある、参加の箱）。

## 2. 全体の地図

```
members/{メールアドレス}                 部員名簿
practiceMenus/{日付}                     練習メニュー
  └ attendance/{メールアドレス}          競技場の日の参加
practiceOptions/main                     メニューの選択肢
settings/fees                            競技場代の料金
settings/sheets                          振り返りのスプレッドシート
records/{自動ID}                         大会記録
meets/{自動ID}                           大会情報
  └ entries/{メールアドレス}             エントリー
reflections/{年月}_{メールアドレス}      月末の振り返り（本人だけが見る部分）
goals/{年月}_{メールアドレス}            来月の目標（全員が見る部分）
moods/{日付}_{メールアドレス}            今日の気分
stabroSessions/{自動ID}                  スタブロの練習記録
pushTokens/{自動ID}                      スマホ通知の宛先
```

| コレクション | 使い始める Step |
| --- | --- |
| members・practiceMenus・attendance・practiceOptions・settings/fees | Step 1 |
| records | Step 2 |
| meets・entries | Step 3 |
| reflections・goals・settings/sheets | Step 4 |
| moods・stabroSessions・pushTokens | Step 5 |

## 3. 共通の決まり

| 決まり | 内容 |
| --- | --- |
| 部員を表す ID | Google アカウントのメールアドレス（小文字）。`members` のドキュメント ID と同じ |
| 日付 | `YYYY-MM-DD` の文字列（例：`2026-10-27`）。日本時間で考え、0 時に切り替わる |
| 年月 | `YYYY-MM` の文字列（例：`2026-11`） |
| 記録の書き方 | 表示用の文字（`mark`）と、並べ替え・グラフ用の数値（`value`）を両方保存する |
| 更新の記録 | 多くのドキュメントに `updatedBy`（最後に編集した人）と `updatedAt`（日時）を持たせる |

記録の書き方

| 種目の種類 | 表示用（mark） | 数値（value） |
| --- | --- | --- |
| 走る種目 | `00:11.52`、`04:35.20` | 秒（11.52、275.20） |
| 距離を測る種目 | `06.12m` | m（6.12） |
| 混成競技 | `2500点` | 点（2500） |

## 4. コレクションごとの形

### members（部員名簿）

ドキュメント ID：メールアドレス（小文字）

| フィールド | 型 | 例 | 説明 |
| --- | --- | --- | --- |
| name | 文字列 | 野田 太郎 | 漢字のフルネーム |
| email | 文字列 | taro@gmail.com | ログインに使う個人の Google アカウント |
| status | 文字列 | approved | `pending`（承認待ち）／`approved`（承認済み）／`rejected`（却下） |
| role | 文字列 | member | `adviser`（顧問）／`captain`／`viceCaptain`／`manager`／`member` |
| isAdmin | 真偽値 | false | 開発者。顧問と同じ権限を持つ |
| graduationYear | 数値 | 2029 | 高校を卒業する年度。学年はここから計算する（顧問は空） |
| bibNumber | 文字列 | 123 | ゼッケン番号 |
| events | 文字列の配列 | ["100m", "200m"] | 専門種目（公式種目の一覧から選ぶ） |
| personalBests | 一覧 | 下の表 | PB（種目ごと） |
| stabroBests | まとまり | {"30m": 4.25, "60m": 7.40, "80m": 9.72} | スタブロの距離ごとのベスト（秒） |
| createdAt | 日時 | | 申請した日時 |
| updatedAt | 日時 | | 最終更新日時 |

personalBests の 1 件

| フィールド | 型 | 例 | 説明 |
| --- | --- | --- | --- |
| event | 文字列 | 100m | 種目 |
| mark | 文字列 | 00:11.52 | 表示用 |
| value | 数値 | 11.52 | 並べ替え・比較用 |
| isWindAssisted | 真偽値 | false | 追い風参考か（「参」の印） |
| date | 文字列 | 2026-10-18 | 出した日（手入力の PB は空） |
| meetName | 文字列 | 〇〇記録会 | 出した大会（手入力の PB は空） |
| recordId | 文字列 | | もとになった大会記録の ID（手入力の PB は空） |
| manualMark | 文字列 | 00:12.05 | 使い始める前に手入力した PB。PB を自動で戻すときの比較に使う |

> 学年は保存しません。`graduationYear` と今日の日付から計算します（4 月 1 日に自動で上がる）。

### practiceMenus（練習メニュー）

ドキュメント ID：日付（例：`2026-10-27`）。1 日 1 件。

| フィールド | 型 | 例 | 説明 |
| --- | --- | --- | --- |
| date | 文字列 | 2026-10-27 | 日付 |
| place | 文字列 | 競技場 | 場所（選択肢から） |
| warmUp | 文字列の配列 | ["10種", "動き作り"] | アップ（選択肢から） |
| items | 一覧 | 下の表 | メニュー（上から順番に並ぶ。「専門」も 1 つの練習として入る） |
| note | 文字列 | スパイク持参 | 連絡事項（自由に書く） |
| isStadium | 真偽値 | true | 競技場の日か（場所で「競技場」を選ぶと自動で true） |
| isWinterRate | 真偽値 | false | 冬季料金をかけるか。全員が切り替えられ、全員に反映される |
| hasStabro | 真偽値 | true | items に「スタブロ」が入っているか（保存時に自動で決まる。「スタブロの記録をつける」ボタンを出すのに使う） |
| updatedBy | 文字列 | | 最後に編集した人 |
| updatedAt | 日時 | | 最終更新日時 |

items の 1 件

| フィールド | 型 | 例 | 説明 |
| --- | --- | --- | --- |
| type | 文字列 | テンポ走 | 練習の種類（選択肢から） |
| distance | 文字列 | 150m | 距離（選択肢から。ない練習は空） |

| フィールド | 型 | 例 | 説明 |

### reflections（月末の振り返り：本人だけが見る部分）

ドキュメント ID：`{年月}_{メールアドレス}`（例：`2026-11_taro@gmail.com`）。1 人 1 か月 1 件。提出したら直せない。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| memberId | 文字列 | 誰の振り返りか |
| month | 文字列 | 何月分か（`2026-11`。25 日に出るフォームの月） |
| lastGoal | 文字列 | 質問 1：先月の目標（途中入部の人は空） |
| achievement | 数値 | 質問 2：達成度 1〜5（途中入部の人は空） |
| review | 文字列 | 質問 3：できたこと・できなかったこと・新しい課題 |
| submittedAt | 日時 | 提出した日時 |

### goals（来月の目標：全員が見る部分）

ドキュメント ID：`{年月}_{メールアドレス}`。振り返りを提出すると、同時に作られる。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| memberId | 文字列 | 誰の目標か |
| month | 文字列 | どの振り返りで書いた目標か |
| goal | 文字列 | 質問 4：来月の目標 |
| submittedAt | 日時 | 提出した日時 |

> **振り返りを 2 つの箱に分ける理由**：Firestore は「1 件のうち、この項目だけ見せない」ができません。質問 1〜3 は本人だけ、質問 4 は全員に見せたいので、箱を分けています。
> 提出状況（28 人中 20 人）と未提出の人は、`goals` にその月の分があるかどうかで判定します。

### moods（今日の気分）

ドキュメント ID：`{日付}_{メールアドレス}`（例：`2026-10-27_taro@gmail.com`）

| フィールド | 型 | 説明 |
| --- | --- | --- |
| memberId | 文字列 | 誰の気分か |
| date | 文字列 | 日付 |
| mood | 文字列 | `great`（絶好調）／`good`（いい感じ）／`normal`（ふつう）／`sleepy`（ねむい）／`tired`（へとへと）／`legPain`（足が痛い）／`sick`（体調悪め） |
| createdAt | 日時 | 選んだ日時 |

> その日のうちは変えられない（作るだけで、上書きはできない）。0 時を過ぎると日付が変わるので、自然にリセットされる。古い日付の分は、あとで自動で消す。

ドキュメント ID：自動。1 人の 1 日分につき 1 件。

| フィールド | 型 | 例 | 説明 |
| --- | --- | --- | --- |
| memberId | 文字列 | taro@gmail.com | 走った人 |
| date | 文字列 | 2026-10-27 | 日付 |
| runs | まとまり | {"30m": [4.30, 4.25], "60m": [7.45, 7.40], "80m": [9.80]} | 1 本ずつのタイム（秒） |

| enteredBy | 文字列 | | 入力した人（測った人） |
| updatedAt | 日時 | | |

| フィールド | 型 | 説明 |
| --- | --- | --- |
| memberId | 文字列 | 誰のスマホか |

## 5. 権限のまとめ

「全員」は、承認済みの部員（顧問を含む）のことです。開発者は、すべての場面で顧問と同じ権限を持ちます。

| データ | 読む | 作る・直す | 消す |
| --- | --- | --- | --- |
| members（自分の申請） | 本人 | 本人（申請時だけ。status は pending、role は member に固定） | ― |
| members（名前・学年・役職） | 全員 | 顧問（承認時は顧問・キャプテンが名前・学年を直せる） | ― |
| members（status：承認・却下） | 全員 | 顧問・キャプテン | ― |
| members（ゼッケン・専門種目・PB） | 全員 | 本人・顧問・キャプテン・マネージャー | ― |
| members（削除） | ― | ― | 顧問・キャプテン（関係するデータもまとめて消す） |
| practiceMenus | 全員 | 顧問・キャプテン・副キャプテン・マネージャー | 同左 |
| practiceMenus の isWinterRate | 全員 | 全員 | ― |
| attendance | 全員 | 本人（自分の分）／顧問・キャプテン・副キャプテン・マネージャー（全員分） | 同左 |
| practiceOptions | 全員 | 顧問・キャプテン・副キャプテン・マネージャー | ― |
| settings/fees | 全員 | 顧問 | ― |
| settings/sheets | 全員 | 顧問 | ― |
| records | 全員 | 本人（自分の分）／顧問・キャプテン・マネージャー（全員分） | 同左 |
| meets | 全員 | 顧問・キャプテン・副キャプテン・マネージャー | 同左 |
| entries | 全員 | 本人（自分の分）／顧問・キャプテン・副キャプテン・マネージャー（全員分） | 同左 |
| reflections | **本人だけ** | 本人（作るだけ。直せない） | ― |
| goals | 全員 | 本人（振り返りの提出と同時に作るだけ） | ― |
| moods | 全員 | 本人（その日の分を作るだけ） | ― |
| stabroSessions | 全員 | 全員（測った人が誰の分でも入力できる） | 本人・顧問・キャプテン・マネージャー |
| pushTokens | 本人 | 本人 | 本人 |

## 6. サーバー側（Vercel）で行う処理

スマホからは直接できない、または安全のためにサーバーで行う処理です。

| 処理 | いつ | 内容 |
| --- | --- | --- |
| スプレッドシートへの書き込み | 振り返りが提出されたとき | 年度のタブの、その月の折りたたみの中に 1 行追加する |
| スプレッドシートの共有 | 部員が承認されたとき・削除されたとき | その人の Google アカウントに閲覧の権限を渡す・外す |
| 部員の削除 | 顧問・キャプテンが削除したとき | members と、その人の records・reflections・goals・moods・stabroSessions・entries・attendance・pushTokens をまとめて消す |
| スマホへの通知 | メニュー登録・申請・25 日・大会の翌日 | pushTokens の宛先に通知を送る |
| 古い気分の掃除 | 毎日 | 前日より古い moods を消す |

> 決まった時刻に動く処理（25 日の通知、毎日の掃除）は、Vercel の定期実行の機能を使います（無料プランで 1 日 1 回まで）。

## 7. 決定ログ

| 日付 | 決めたこと | 理由 |
| --- | --- | --- |
| 2026-10-25 | データの形を 1 つの資料にまとめ、この資料を正とする | Step ごとに分かれていて全体が見えにくかったため |
| 2026-10-25 | 振り返りを reflections（本人だけ）と goals（全員）の 2 つに分ける | Firestore は項目ごとに見せる人を変えられないため |
| 2026-10-25 | members に rejected（却下）の状態を足す | 却下された人に「申請が通りませんでした」と出すため |
| 2026-10-25 | 部員の削除・スプレッドシートの書き込みと共有・通知は、サーバー側で行う | 関係するデータをまとめて消したり、Google のサービスを使ったりするため |
| 2026-11-01 | records の resultUrl をなくし、meetId を必ず入れる | 記録は登録済みの大会からだけ入力することにしたため |
| 2026-11-01 | practiceMenus の general・special を items 1 つにまとめ、「専門」は練習の種類の 1 つにする | メニューを全体・専門に分けず、1 つの並びで見せるため |
